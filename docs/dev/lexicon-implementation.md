# Lexiconレコードのインデックス実装ガイド

新しいレコードタイプ（例: app.bsky.graph.list）をworkerでインデックスするときの流れです。迷ったら、app.bsky.graph.followの実装をなぞってください。

## データの流れ

workerは、Tapから受け取ったレコードもPDSから取得したレコードも、IndexRecordServiceの1つの流れで処理します。レコードタイプごとの知識（変換、保存、そのレコードが指すもの）は、`application/services/indexer` のタイプごとのファイルに書きます。手元にないものだけ取得する、通知はライブのときだけ作る、といったタイプによらない決まりと、ジョブの予約は、共通の流れが行います。

## 手順

| 順  | やること                                                                             |
| --- | ------------------------------------------------------------------------------------ |
| 1   | Lexicon定義を取得し、クライアントのコードを生成する。定義ファイルは手で書かない      |
| 2   | データベースにテーブルを追加し、マイグレーションを作る                               |
| 3   | レコードをDBに依存しない型に変換する処理を作り、対応するコレクションの一覧に足す     |
| 4   | Repositoryのインターフェースと実装、テスト用のインメモリ実装を作る                   |
| 5   | `application/services/indexer` にタイプのindexerを作り、collection-indexers.tsに足す |
| 6   | RepositoryをDIに登録し、テストではインメモリ実装に差し替える                         |
| 7   | indexerに、必要なメソッドだけを足す                                                  |
| 8   | 変更したサービスとRepositoryのテストを書き、pnpm allを通す                           |

indexerのメソッドは次のとおりです。parse以外は、必要なものだけ書きます。どれも値を返すだけで、ジョブの予約はしません。

| メソッド                              | 決めること                                                       |
| ------------------------------------- | ---------------------------------------------------------------- |
| parse                                 | レコードを検証して変換する                                       |
| shouldStore                           | 保存するかどうか                                                 |
| save                                  | タイプごとのテーブルへの保存                                     |
| recordsToFetch                        | PDSから取りに行きたいレコード                                    |
| accountsToFetch                       | プロフィールとハンドルが要るアカウント（作者は共通の流れが足す） |
| notificationCandidates                | 通知の候補                                                       |
| postsToAggregate、accountsToAggregate | 保存・削除のあとに集計し直す投稿とアカウント                     |
| reposToSync                           | 保存・削除のあとに追跡を見直すアカウント                         |

タイプによらない決まりは次の場所にあります。

| 場所                      | 決まり                                                              |
| ------------------------- | ------------------------------------------------------------------- |
| FetchPolicyService        | 手元にないものだけ取得する、Tapから2段先まで                        |
| NotificationPolicyService | ライブのときだけ、メンバー宛てだけ、自分宛ては除く、同じ相手には1件 |
| IndexJobService           | ジョブの予約（コミット後）                                          |
