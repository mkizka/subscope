# プッシュ通知

## 概要

メンバー宛ての通知が追加されたときに、SubscopeのwebクライアントへWeb Push(VAPID)でプッシュ通知を送る。外部サービスは使わず、workerがブラウザのプッシュサーバー(FCM、Mozilla、Appleなど)へ直接送る。振る舞いは[Workerの通知の仕様](../specs/worker/notification.md)の「プッシュ通知の送信」と、Webの通知の仕様の「プッシュ通知」で決め、このファイルには設計と理由だけを書く。

## 方針

| 方針                                | 理由                                                                                                                                                      |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象はSubscopeのwebクライアントだけ | 公式アプリのプッシュはBlueskyの鍵で送られ、PDSはregisterPushを本文のserviceDidへ転送するため、Subscopeからは送れない。公式アプリにはBlueskyから届き続ける |
| 外部サービスを使わない              | VAPIDの鍵を環境変数に入れるだけで動くようにし、セルフホストの手間を増やさない                                                                             |
| 鍵がなければ機能を出さない          | 鍵は本番でも任意にし、設定し忘れてもデプロイ直後に止まらないようにする                                                                                    |
| 端末ごとのオプトイン                | 本人が切り替えを押したときだけ購読する。設定はアカウントではなく端末に付く                                                                                |
| 本文に名前と投稿を入れる            | 本文は端末の鍵で暗号化されるので、プッシュサーバーには読まれない                                                                                          |

## 全体の流れ

| 場所     | 処理                                                                                    |
| -------- | --------------------------------------------------------------------------------------- |
| web      | 切り替えをオンにすると、ブラウザが購読を作り、webがそれをDBに保存する                   |
| worker   | Tapからリアルタイムに受け取ったレコードで通知を新しく作り、コミット後に送信ジョブを積む |
| worker   | ジョブが購読を読み、暗号化してプッシュサーバーへ送る                                    |
| ブラウザ | Service Workerが通知を出し、タップで /notifications を開く                              |

## 購読

- 購読は、ブラウザが発行する送り先のURLと、本文の暗号化に使う端末の鍵2つからなる。アカウントを消すと購読も消える
- 1つの端末は1件。同じ端末で別のアカウントがオンにしたら上書きする。共有の端末では、最後にオンにしたアカウントの通知だけが届く
- 1アカウントあたりの端末数に上限はない。メンバーは招待制で、悪用で増えすぎる心配が小さいため

## 環境変数

| 変数              | 使う場所    | 用途                                   |
| ----------------- | ----------- | -------------------------------------- |
| VAPID_PUBLIC_KEY  | web, worker | ブラウザの購読と、送信時の署名に使う   |
| VAPID_PRIVATE_KEY | worker      | 送信時の署名に使う                     |
| VAPID_SUBJECT     | worker      | プッシュサーバーに伝える運営者の連絡先 |

- 開発とE2Eでは、コミットした既定値を使う。webとworkerで同じ公開鍵にする
- 本番では3つとも任意。webに公開鍵がなければ購読が作られないので、workerにも何も届かない

## worker

### いつ送るか

送るかどうかの判定は持たず、通知を新しく作ったら必ず送る。どの通知を作るかは、[Workerの通知の仕様](../specs/worker/notification.md)の「通知の生成」だけで決める。

- 通知の保存は1か所にまとめ、各indexerはそこを通す。重複は無視し、新しく入った通知だけを送る
- workerが止まっていた間のイベントも、再開後に遅れて送る。まだ見ていない通知なので、古くても送る

ジョブには通知を特定するキーだけを入れ、中身は実行時にDBから読む。

- 通知を作る処理で、名前や本文の読み込みを増やさない
- 通知の項目を変えても、デプロイをまたいで残ったジョブが壊れない
- 送る前に通知が取り消されていれば(いいねの取り消しなど)、送らずに済む

### ジョブ

- リトライしない。既存のリトライ間隔(最短10秒、最長1日)では、遅れて届く通知に意味がないため
- 通知が消えているか、購読がなければ何もしない
- 購読ごとに送る。1台の失敗は他の端末に影響させず、ログに残すだけにする
- プッシュサーバーが404か410を返した購読は、端末側で解除されたものとして削除する
- 有効期限は24時間。端末がオフラインの間はプッシュサーバーが預かり、過ぎたら捨てる
- 暗号化はweb-pushライブラリで行い、送るのはNode.jsのfetchで行う。web-pushの送信関数はhttpsにしか送れず、E2Eでローカルの受け口に送れないため

### 本文

本文はタイトル・本文・タグの3つを持つ。

| 理由       | タイトル                       | 本文             |
| ---------- | ------------------------------ | ---------------- |
| いいね     | {名前}さんがいいねしました     | 対象の投稿の本文 |
| リポスト   | {名前}さんがリポストしました   | 対象の投稿の本文 |
| フォロー   | {名前}さんにフォローされました | 空               |
| 返信       | {名前}さんが返信しました       | その投稿の本文   |
| 引用       | {名前}さんが引用しました       | その投稿の本文   |
| メンション | {名前}さんがメンションしました | その投稿の本文   |

- タイトルは通知ページと同じ文にする。名前は表示名、なければハンドル、それもなければDID
- 投稿を保存していなければ本文は空にする。投稿は300文字以内でWeb Pushの上限4KBに収まるので、切り詰めない
- タグは、いいね・リポストなら種類と対象の投稿、それ以外は通知のレコードにする。同じタグの通知は端末上で置き換わるので、1つの投稿へのいいねが続いても1件にまとまる

## web

### 購読の保存

ログインが必要なAPIで、VAPIDの公開鍵の取得、購読の保存、削除を行う。

- appviewを経由せず、OAuthのセッションと同じくwebからDBに直接書く。webクライアントだけの関心で、XRPCとして公開する必要がないため
- 本番では、送り先がhttpsのものだけを受け付ける。workerが任意のURLへ送らないようにするため

### Service Worker

- ビルドしない素のJSで、プッシュを受けて通知を出すことと、タップで /notifications を開くことだけを行う
- 切り替えをオンにしたときに初めて登録する。オフライン動作には使わない

### 切り替えの状態

ブラウザと端末の状態から、次のどれかに決める。上から順に判定し、表示はWebの通知の仕様の「プッシュ通知」で決める。

| 状態     | 条件                                                               |
| -------- | ------------------------------------------------------------------ |
| 使えない | サーバーに公開鍵がない                                             |
| 非対応   | ブラウザにService Worker・Push API・Notification APIのどれかがない |
| ブロック | ブラウザで通知がブロックされている                                 |
| オン     | この端末に購読がある                                               |
| オフ     | それ以外                                                           |

- 状態はサーバーに問い合わせず、ブラウザで決める
- 読み込みに失敗したときとSSRでは、何も出さない
- オンにするときは許可を求めてから購読して保存し、オフにするときは購読を解除して削除する

### ログアウト

ログアウトするときは、その端末の購読を解除して削除する。共有の端末で、ログアウトした人の通知が届き続けないようにするため。解除に失敗してもログアウトは続ける。

## テスト

- workerは、Tapのイベントからジョブの実行までを通し、送信をin-memoryに差し替えて送った内容を確かめる
- webのE2Eは、テストの中で立てたHTTPサーバーを受け口にし、ブラウザの購読をその受け口と本物の鍵に差し替える。workerが本当に暗号化して送るところまで通すため
- 「送らない」ことは、届かないのを待って確かめない。後から登録した別の端末に届いたことを確かめてから、先の端末に届いていないことを見る。同じ通知は1つのジョブで全端末に送るので、これで決まる
- 状態ごとの見た目はstoryのplayテストにする
