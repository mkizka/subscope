# Worker仕様: バックフィル

## Tapへの追加

追跡アカウントをTapに追加して、そのレコードを受け取る。追跡アカウントかどうかが変わりうる操作のあとに、その時点のDBの状態から追加するか外すかを決める。

| ID    | 仕様                                                                          |
| ----- | ----------------------------------------------------------------------------- |
| tap-1 | メンバーがフォローしたアカウントをTapに追加する                               |
| tap-2 | メンバー以外のフォローではTapに追加しない                                     |
| tap-3 | メンバーがフォローを外したアカウントは、追跡アカウントでなくなればTapから外す |
| tap-4 | 他のメンバーがフォローしているアカウントはTapから外さない                     |
| tap-5 | メンバー以外がフォローを外してもTapから外さない                               |
| tap-6 | メンバーはフォローを外されてもTapから外さない                                 |

## バックフィルの状態の確認

Tapに追加したアカウントの過去のレコードを、Tapが同期し終えたかを確認して保存する。webはこれを読んで、メンバーにバックフィルが終わったかを知らせる。

| ID         | 仕様                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| backfill-1 | Tapに追加したアカウントのバックフィルの状態を確認する                             |
| backfill-2 | Tapの状態を、エラー・同期中・完了のどれかに分けて保存する                         |
| backfill-3 | 完了でなければ、間隔を伸ばしながら確認を続ける                                    |
| backfill-4 | 追跡アカウントでなくなったアカウントは確認しない                                  |
| backfill-5 | 起動時に、状態をまだ確認していない追跡アカウントを確認する                        |
| backfill-6 | リレーが削除済みと答えるエラーのアカウントは、Tapから外して完了とし、確認を止める |

| Tapの状態                          | 保存する状態 |
| ---------------------------------- | ------------ |
| error                              | エラー       |
| pending、desynchronized、resyncing | 同期中       |
| それ以外                           | 完了         |

Tapは失敗したバックフィルを自動で再試行するので、エラーでも確認を続ける。停止・凍結されたアカウントはこれ以上レコードが届かないので完了とみなす。確認の間隔は10秒から最長10分まで伸ばす。完了はTapが送り終えた時点なので、Workerが保存し終えるまでには数分かかる。
