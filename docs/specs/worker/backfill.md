# Worker仕様: バックフィル

## Tapへの追加

追跡アカウントをTapに追加して、そのレコードを受け取る。追跡アカウントかどうかが変わりうる操作のあとに、その時点のDBの状態から追加するか外すかを決める。

| ID     | 仕様                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| tap-1  | メンバーがフォローしたアカウントをTapに追加する                                     |
| tap-2  | メンバー以外のフォローではTapに追加しない                                           |
| tap-3  | メンバーがフォローを外したアカウントは、追跡アカウントでなくなればTapから外す       |
| tap-4  | 他のメンバーがフォローしているアカウントはTapから外さない                           |
| tap-5  | メンバー以外がフォローを外してもTapから外さない                                     |
| tap-6  | メンバーはフォローを外されてもTapから外さない                                       |
| tap-7  | Tapに追加するときに、追跡を始めた時刻を記録する                                     |
| tap-8  | すでに追跡しているアカウントの、追跡を始めた時刻は変えない                          |
| tap-9  | Tapから外したら、追跡を始めた時刻を消す                                             |
| tap-10 | 登録されたアカウントは、Tapに追加済みでも外して追加し直し、全レコードを受け取り直す |

追跡アカウントはメンバーと、メンバーがフォローしているアカウント。登録とフォローの2つから決まるので、追跡アカウントかどうかが変わりうる操作は次の4つになる。どの操作でも、そのあとに表のアカウントをTapに追加するか外すかを見直す。

| 操作                     | 見直すアカウント             | 仕様項目                                     |
| ------------------------ | ---------------------------- | -------------------------------------------- |
| メンバーがフォローする   | フォロー先                   | tap-1                                        |
| メンバーがフォローを外す | フォロー先                   | tap-3、tap-4                                 |
| 登録する                 | 本人と、保存済みのフォロー先 | registerAccount-7、registerAccount-9、tap-10 |
| 登録を解除する           | 本人と、フォロー先           | unregisterAccount-1                          |

登録やフォローを変える操作を新しく足すときは、この表に行を足す。

フォロー先として追跡している間は保存しないレコードがあるので、登録されたらメンバーとして全レコードを受け取り直す。Tapは追加済みのアカウントをもう一度追加しても何も送らず、外すと送信済みの記録を消すので、外してから追加する。Tapにないアカウントを外しても何も起きないので、初めての登録でも同じ手順にする。

追跡を始めた時刻は、過去のレコードをどこまで保存するかを決める起点になる。レコードを受け取った時刻を起点にすると、処理の遅れやTapの再同期で、追跡を始めたあとのレコードまで古いとみなしてしまう。Tapから外して追加し直したアカウントは、追加し直した時刻が新しい起点になる。

## バックフィルの状態の確認

Tapに追加したアカウントの過去のレコードを、Tapが同期し終えたかを確認して保存する。webはこれを読んで、メンバーにバックフィルが終わったかを知らせる。

| ID         | 仕様                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| backfill-1 | Tapに追加したアカウントのバックフィルの状態を確認する                             |
| backfill-2 | Tapの状態を、エラー・同期中・完了のどれかに分けて保存する                         |
| backfill-3 | 完了でなければ、間隔を伸ばしながら確認を続ける                                    |
| backfill-4 | 追跡アカウントでなくなったアカウントは確認しない                                  |
| backfill-5 | 起動時に、状態をまだ確認していない追跡アカウントを確認する                        |
| backfill-6 | リレーが削除済みと答えるエラーのアカウントは、Tapから外して完了とし、確認を止める |
| backfill-7 | 削除済みでTapから外したアカウントは、追跡を始めた時刻も消す                       |

| Tapの状態                          | 保存する状態 |
| ---------------------------------- | ------------ |
| error                              | エラー       |
| pending、desynchronized、resyncing | 同期中       |
| それ以外                           | 完了         |

Tapは失敗したバックフィルを自動で再試行するので、エラーでも確認を続ける。停止・凍結されたアカウントはこれ以上レコードが届かないので完了とみなす。確認の間隔は10秒から最長10分まで伸ばす。完了はTapが送り終えた時点なので、Workerが保存し終えるまでには数分かかる。
