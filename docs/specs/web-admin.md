# 管理画面仕様

管理者がサーバーを運用するための画面の振る舞いを定める。

最初の管理者は、サーバーに最初にログインしたアカウントとする（[login-1](./web-client.md#ログイン)）。

「確認のうえ」行う操作では、何が起きるかを本文に書いたダイアログを出す。サーバー登録の停止や削除のような危険な操作は、確定ボタンを赤にする。

## 管理画面へのアクセス

管理画面はログイン後の3カラムレイアウトの中央カラムに出す。

- admin-1: 左カラムのメニューの下の「サーバー管理」に、管理者にだけ「アカウント管理」「招待コード」「ジョブキュー」を出す
- admin-2: 管理者でないアカウントが管理画面のURLを開くと403エラーを出す

## メンバー

`/admin/registered-accounts` でメンバーを管理する。管理者の付与には appview の API の追加が必要。

- admin-accounts-1: メンバーを新しい順に1人1行で並べ、名前・ハンドル・管理者かどうか・登録日を出す
- admin-accounts-2: 管理者でないメンバーを、行の右端のメニューから確認のうえ「サーバー登録を停止する」と登録を解除し、そのアカウントは招待コードで再登録できなくなる
- admin-accounts-3: 管理者でないメンバーを、行の右端のメニューから確認のうえ「管理者にする」で管理者にできる
- admin-accounts-4: 見出しの横にメンバーの人数を出す
- admin-accounts-5: 「メンバー」「停止中」のタブで一覧を切り替える
- admin-accounts-6: 「停止中」タブには、サーバー登録を停止したアカウントを1人1行で並べ、名前・ハンドルを出す
- admin-accounts-7: 停止中のアカウントを、行の「登録を再開する」から確認のうえ再開すると一覧から消え、そのアカウントは招待コードで再登録できるようになる
- admin-accounts-8: 選んだタブをURLに残し、そのURLを開くと同じタブを出す
- admin-accounts-9: 「メンバー」タブの各行に、本人の過去の投稿の同期状態を「同期済み」「同期中」「同期エラー」のバッジで出す
- admin-accounts-10: メンバーの一覧を開くと、読み込みを待たずに画面を表示し、読み込み終えるまでスケルトンを表示する

同期状態は、メンバーのタイムラインに過去の投稿がそろったかを管理者が確かめるために出す。対応が必要なものが目立つように、同期エラーだけ赤にする。

## 招待コード

`/admin/invite-codes` で招待コードを管理する。

- invite-codes-1: 招待コードを新しい順に1件1行で並べ、各行にコード・状態（未使用・使用済み・期限切れ）・使用者・有効期限・作成日を出す
- invite-codes-2: 一覧の下までスクロールすると続きを読み込む
- invite-codes-3: 「新規作成」で有効期限7日の招待コードを作り、一覧の先頭に出す
- invite-codes-4: 未使用で期限内の招待コードは、確認のうえ削除できる
- invite-codes-5: 使用済みの招待コードは削除できない
- invite-codes-6: 期限切れの招待コードは確認せずに削除できる
- invite-codes-7: 未使用で期限内の招待コードは、コードの横のボタンでコードをクリップボードにコピーできる
- invite-codes-8: 使用済みの招待コードには、使用者のアバターと名前を出す
- invite-codes-9: 招待コードの一覧を開くと、読み込みを待たずに画面を表示し、読み込み終えるまでスケルトンを表示する

状態のバッジは、使える招待コードがひと目で分かるように未使用だけ緑にし、使用済みと期限切れは灰色にする。

## ジョブキュー

`/admin/bull-board` で bull-board の画面を3カラムレイアウトの外にそのまま出す。

- bull-board-1: 左カラムの「ジョブキュー」は、新しいタブを開くことが分かるアイコンを付け、新しいタブで開く
- bull-board-2: `Authorization: Bearer {ADMIN_API_TOKEN}` を付けると、ログインせずに bull-board のAPI(`/admin/bull-board/api/` 以下)をGETで読める
- bull-board-3: `ADMIN_API_TOKEN` では、bull-board のAPIをGET以外で呼べない

運用時にClaudeなどがジョブの件数や失敗理由を調べられるように、読み取り専用のトークンを用意する。例えば `/admin/bull-board/api/queues?activeQueue=fetchRecord&status=failed` で、各キューの件数と、fetchRecordの失敗したジョブの理由を返す。`ADMIN_API_TOKEN` を設定しなければトークンでは読めない。
