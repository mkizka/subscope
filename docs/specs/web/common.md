# Web仕様: 共通

メンバーが使うWebクライアントで、画面をまたいで共通するルールを定める。

## レイアウト

画面の幅でPCとモバイルの表示を切り替える。メニューはホーム・検索・通知・リスト・プロフィール・サーバー・設定で、管理者には管理画面も出す。

| 表示     | 構成                                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| PC       | 3カラム。左はサーバー名とメニューと新規投稿ボタンと自分のアカウント、中央は選んだ画面、右は検索ボックスと「サーバーについて」カード                          |
| モバイル | 中央だけを出す。上のヘッダーに自分のアイコンとロゴ、下にホーム・検索・通知・プロフィールのタブ、右下に新規投稿ボタンを置く。自分のアイコンからドロワーを開く |

| ID         | 仕様                                                                                                             |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| layout-s1  | 左カラムのメニューで、今いるページの項目を強調する                                                               |
| layout-s2  | 左カラムのアカウント欄に、自分のハンドルを表示する                                                               |
| layout-e2  | ページの読み込み中は、画面上部にプログレスバーを表示する                                                         |
| layout-s3  | 右カラムに、Subscopeを紹介する「サーバーについて」カードを表示し、カード全体を `/server` へのリンクにする        |
| layout-s4  | モバイルでは、下のタブで今いるページの項目を強調する                                                             |
| layout-s5  | モバイルのドロワーには、PCの左カラムと同じメニューを並べる                                                       |
| layout-e4  | `/server` では右カラムのカードを表示せず、中央カラムの位置は他のページと変えない                                 |
| layout-s6  | メニューの「サーバー」から `/server` に移動できる                                                                |
| layout-s15 | メニューの「設定」から `/settings` に移動できる                                                                  |
| layout-e5  | 右カラムの検索ボックスでEnterを押すと、`/search?q=検索語` に移動する                                             |
| layout-s10 | モバイルのタブのあるページでは、ヘッダーを隠すとタブだけを画面上端に残し、ヘッダーを再び出すとタブもその下に戻す |
| layout-s11 | `/search` では、右カラムの検索ボックスを表示しない                                                               |
| layout-e6  | モバイルでは、下にスクロールするとヘッダーを隠し、上にスクロールすると再び表示する                               |
| layout-s12 | スケルトンは、左から右へ光が流れるアニメーションにする                                                           |
| layout-s13 | モバイルの下のタブは、ラベルを出さずアイコンだけにする                                                           |
| layout-s16 | モバイルでタブが画面上端に届く前にヘッダーが隠れても、タブはその場から動かさない                                 |
| layout-s14 | 重なり順は下から、本文・埋め込み、浮かせた表示、固定の見出し、固定の下タブ、検索候補の順にする                   |
| layout-e7  | 右カラムの検索ボックスに入力すると合うアカウントの候補を出し、候補を選ぶとそのプロフィールに移動する             |

スケルトンの行は、表示後に高さがずれないよう、実際の行（投稿・アカウント・通知・リスト）と同じ形にする。プログレスバーは進み具合が分からないため、流れ続けるアニメーションにする。

## 同期状態の表示

メンバーを表示する場所（プロフィール、アカウントの一覧、管理画面のメンバー一覧）で、過去の投稿をどこまで取り込んだかを示す。

| ID            | 仕様                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| syncStatus-s1 | メンバーには、過去の投稿の同期状態を「同期中」「同期済み」「同期エラー」のバッジで表示する |

状態はWorkerが保存したもの（[バックフィルの状態の確認](../worker/backfill.md#バックフィルの状態の確認)）を使い、まだ確認していなければ同期中とする。対応が必要なものが目立つよう、同期エラーだけ赤にする。

## 読み込み中のスケルトン

どの画面も、データの読み込みを待たずに表示する。

| ID          | 仕様                                                                                 |
| ----------- | ------------------------------------------------------------------------------------ |
| skeleton-s1 | 画面は読み込みを待たずに表示し、読み込み終えるまでデータの場所にスケルトンを表示する |

## 送信中のスピナー

送信や切り替えの結果を待つ操作は、二重に実行されないようにする。

| ID            | 仕様                                                                     |
| ------------- | ------------------------------------------------------------------------ |
| submitting-s1 | ボタンやスイッチは、送信や切り替えが終わるまでスピナーを出して無効にする |

## 戻ったときのキャッシュ

画面の内容はブラウザでキャッシュし、戻ったときはキャッシュを表示してから裏で読み込み直す。戻るたびに読み込みを待たされないようにするため。

| ID       | 仕様                                                                 |
| -------- | -------------------------------------------------------------------- |
| cache-e1 | 一度表示した画面に戻ると、読み込み直しを待たずに前回の内容を表示する |

## 検索履歴

右カラムの検索ボックスと検索画面の検索欄で、同じ検索履歴を使う。履歴はブラウザに保存し、サーバーには送らない。同じ語を検索し直すと先頭に移る。

| ID               | 仕様                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------ |
| searchHistory-s1 | 検索欄にフォーカスして何も入力していないとき、検索した語を新しい順に最大10件表示する |
| searchHistory-s2 | 履歴の語を選ぶと、その語で検索する                                                   |
| searchHistory-s3 | 履歴の語は1件ずつ、または「履歴を全て削除」でまとめて削除できる                      |

## 起動時のスプラッシュ

ログイン後の最初の表示では、メニューやアバターが後から現れて画面が動かないよう、自分の情報が届くまで全画面のスプラッシュを出す。画面の内容はその裏で並行して読み込む。

| ID        | 仕様                                                                             |
| --------- | -------------------------------------------------------------------------------- |
| splash-e1 | 自分の情報が届くまで、ロゴとプログレスバーを全画面で表示する                     |
| splash-e2 | 自分の情報が届くと、スプラッシュを消してメニューとアバターが揃った画面を表示する |
| splash-e3 | アプリ内でページを移動したときは、スプラッシュを表示しない                       |
| splash-e4 | JSの読み込み前から、サーバーが返すHTMLにスプラッシュを含める                     |
| splash-e5 | 自分の情報が届くと、スプラッシュを約300msかけてフェードして消す                  |
| splash-e6 | 動きを減らす設定のブラウザでは、フェードせずにスプラッシュを消す                 |
| splash-e7 | 自分の情報の取得に失敗したときは、再試行を待たずにスプラッシュを消す             |

## エラー

存在しないページや読み込みに失敗したページでは、見出し・説明・「ホームに戻る」ボタンを中央のカードに出し、ステータスコードをその下に小さく出す。

| ID       | 仕様                                                          |
| -------- | ------------------------------------------------------------- |
| error-e1 | 存在しないページでは「ページが見つかりません」と404を表示する |
| error-s1 | 「ホームに戻る」を押すとトップページに移動する                |

## PWA

ホーム画面にアプリとしてインストールできるようにする。Service Workerはプッシュ通知のためだけに使い、オフラインでは動かさない。

| ID     | 仕様                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------- |
| pwa-e1 | マニフェストで、名前・アイコン・独立したウィンドウでの表示・開始ページ・背景色に合わせたテーマ色を宣言する |
| pwa-e2 | すべてのページで、マニフェストとホーム画面用のアイコンを参照する                                           |
