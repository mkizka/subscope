# Web仕様: 共通

メンバーが使うWebクライアント（apps/web）の画面と操作の振る舞いを定める。各項目はE2Eテスト（`e2e`）かStorybookのplayテストで検証する。

## レイアウト

PCでは3カラムで表示する。左はアイコンとサーバー名とアイコン付きのメニュー（ホーム・検索・通知・リスト・プロフィール・サーバー・設定、管理者には下に管理画面への移動）と新規投稿ボタンと自分のアカウント、中央は左で選んだもの、右は検索ボックスと「サーバーについて」カードにする。

- layout-s1: 左カラムのメニューで、今いるページの項目を強調する
- layout-s2: 左カラムのアカウント欄に、自分のハンドルを表示する
- layout-e2: ページの読み込み中は画面上部に読み込み中のプログレスバーを表示する
- layout-s3: 右カラムに、見出し「サーバーについて」と「SubscopeはBlueskyでフォローしている人の投稿だけが流れる分散SNSです。」を出したカードを表示し、カード全体を `/server` へのリンクにする
- layout-s4: モバイルでは下のタブで今いるページの項目を強調する
- layout-s5: モバイルのドロワーにはPCの左カラムと同じメニュー項目を並べる
- layout-e4: `/server` では、同じ内容の重複を避けるため右カラムのカードを表示せず、中央カラムの位置は他のページと変えない
- layout-s6: 左カラムとモバイルのドロワーのメニューの「サーバー」から `/server` に移動できる
- layout-s15: 左カラムとモバイルのドロワーのメニューの「設定」から `/settings` に移動できる
- layout-e5: 右カラムの検索ボックスで検索語を入力してEnterを押すと、`/search?q=検索語` に移動する
- layout-s10: モバイルでは、タブのあるページ（タイムライン・プロフィール・サーバーなど）は、ヘッダーを隠すとタブだけを画面上端に残し、ヘッダーの再表示と同時にタブをその下へ戻す
- layout-s11: `/search` では、中央に検索欄があるため右カラムの検索ボックスを表示しない
- layout-e6: モバイルでは下にスクロールするとヘッダーを隠し、上にスクロールすると自分のアイコンを含むヘッダーを再び表示する
- layout-s12: スケルトンは、左から右へ光が流れるアニメーションで読み込み中であることを示す
- layout-s13: モバイルでは下のタブにラベル文字を出さず、アイコンだけを表示する
- layout-s16: モバイルでタブがまだ画面上端に届いていないうちにヘッダーが隠れても、タブはその場から動かさず、下の投稿との間に隙間を作らない
- layout-s14: 重なり順は下から、本文・埋め込み、浮かせた表示、固定の見出し、固定の下タブ、検索候補の順にする
- layout-e7: 右カラムの検索ボックスに入力すると、入力に合うアカウントの候補（アイコン、表示名、ハンドル）を下に表示し、候補を選ぶとそのアカウントのプロフィールに移動する

スケルトンの行は、表示後に高さが大きくずれないよう、実際の行（投稿・アカウント・通知・リスト）と同じ形にする。アカウント一覧（フォロー・フォロワー・サーバー・検索・リストのメンバー）は名前・ハンドル・自己紹介・バッジの4段、リスト一覧はアイコンと名前・説明の2段にする。

プログレスバーは進み具合が分からないため、左から右へ流れ続けるアニメーションで読み込み中であることを示す。

画面幅が `lg` 未満のときはモバイル表示にする。中央を基本画面とし、左右のカラムは表示しない。ヘッダーは左に自分のアイコン、中央にロゴを置き、下にホーム・検索・通知・プロフィールのタブ、右下に新規投稿ボタンを置く。自分のアイコンから開くドロワーには、左カラムと同じメニューを並べる。

## 検索履歴

右カラムの検索ボックスと `/search` の検索欄で、同じ検索履歴を使う。検索履歴はブラウザのlocalStorageに保存し、サーバーには送らない。同じ語を検索し直したときは先頭に移動する。

- searchHistory-s1: 検索欄にフォーカスして何も入力していないとき、過去に検索した語を新しい順に最大10件、検索欄の下に表示する
- searchHistory-s2: 履歴の語を選ぶと、その語で検索する
- searchHistory-s3: 履歴の語は個別に、または「履歴を全て削除」で全て削除できる

## 起動時のスプラッシュ

ログイン後の最初の表示では、メニューやアバターが後から現れて画面が動かないよう、自分の情報（`/api/me`）が届くまで全画面のスプラッシュを表示する。メインの内容の取得はスプラッシュの裏で並行して進める。

- splash-e1: 自分の情報の取得が終わるまで、ロゴと読み込み中のプログレスバーを全画面で表示する
- splash-e2: 自分の情報の取得が終わると、スプラッシュを消してメニューとアバターが揃った画面を表示する
- splash-e3: アプリ内でページを移動したときは、スプラッシュを表示しない
- splash-e4: JSが読み込まれる前から、サーバーが返すHTMLにスプラッシュを含める
- splash-e5: 自分の情報の取得が終わると、スプラッシュを約300msかけてフェードして消す
- splash-e6: `prefers-reduced-motion` が有効なときは、フェードせずにスプラッシュを消す
- splash-e7: 自分の情報の取得に失敗したときは、再試行を待たずにスプラッシュを消す

## エラー

存在しないページや読み込みに失敗したページでは、中央そろえのカードに見出し・説明・「ホームに戻る」ボタンを出し、ステータスコードはその下に小さく出す。

- error-e1: 存在しないページを開くと「ページが見つかりません」とステータスコード404を表示する
- error-s1: 「ホームに戻る」を押すとトップページに移動する

## PWA

ブラウザやOSのホーム画面にアプリとしてインストールできるようにする。Service Workerはプッシュ通知のためだけに使い、オフライン動作には対応しない。

- pwa-e1: Web App Manifestで、名前・アイコン・`display: standalone`・`start_url`・DESIGN.mdのsurfaceに合わせたテーマ色を宣言する
- pwa-e2: すべてのページのheadでManifestとapple-touch-iconを参照する
