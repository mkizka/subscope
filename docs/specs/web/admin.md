# Web仕様: 管理画面

管理者がサーバーを運用するための画面の振る舞いを定める。

「確認のうえ」行う操作では、何が起きるかを書いたダイアログを出す。メンバーから外す、削除するといった危険な操作は、確定ボタンを赤にする。

## 管理画面へのアクセス

管理画面はログイン後の3カラムレイアウトの中央カラムに出す。

| ID       | 仕様                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| admin-e1 | 管理者にだけ、左カラムの「サーバー管理」に「アカウント管理」「招待コード」「ジョブキュー」を出す |
| admin-e2 | 管理者でないアカウントが管理画面を開くと403エラーを出す                                          |

## メンバー

`/admin/registered-accounts` でメンバーを管理する。

| ID               | 仕様                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- |
| adminAccounts-e1 | メンバーを新しい順に並べ、名前・ハンドル・管理者かどうか・登録日を出す                                           |
| adminAccounts-e2 | 管理者でないメンバーは、確認のうえ「メンバーから外す」で登録を解除でき、そのアカウントは招待コードで再登録できる |
| adminAccounts-e3 | 管理者でないメンバーは、確認のうえ「管理者にする」で管理者にできる                                               |
| adminAccounts-s3 | 見出しの横の「メンバーを追加」で、ハンドルかDIDを入力するダイアログを開く                                        |
| adminAccounts-e7 | 追加ダイアログで入力したアカウントを、本人のログインなしでメンバーにして一覧の先頭に出す                         |
| adminAccounts-e8 | メンバーに追加できないときは、ダイアログを閉じずに理由（見つからない・すでにメンバー・登録停止中）を出す         |
| adminAccounts-s4 | メンバーは、アバターや名前を押すとそのアカウントのプロフィールを開く                                             |

同期状態は、メンバーのタイムラインに過去の投稿がそろったかを確かめるために出す。

追加したメンバーは通常の登録と同じ扱いで、一覧の見た目も区別しない。

## 招待コード

`/admin/invite-codes` で招待コードを管理する。

| ID             | 仕様                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| inviteCodes-e1 | 招待コードを新しい順に並べ、コード・状態（未使用・使用済み・期限切れ）・使用者・有効期限・作成日を出す |
| inviteCodes-e2 | 一覧の下までスクロールすると続きを読み込む                                                             |
| inviteCodes-e3 | 「新規作成」で有効期限7日の招待コードを作り、一覧の先頭に出す                                          |
| inviteCodes-e4 | 未使用で期限内の招待コードは確認のうえ削除できる                                                       |
| inviteCodes-s1 | 使用済みの招待コードの削除ボタンは押せない                                                             |
| inviteCodes-e5 | 期限切れの招待コードは確認せずに削除できる                                                             |
| inviteCodes-s2 | 未使用で期限内の招待コードは、横のボタンでクリップボードにコピーできる                                 |
| inviteCodes-s3 | 使用済みの招待コードには使用者のアバターと名前を出す                                                   |

状態のバッジは、使える招待コードがひと目で分かるように未使用だけ緑にし、ほかは灰色にする。

## ジョブキュー

`/admin/bull-board` で、ジョブキューの管理画面（bull-board）を3カラムレイアウトの外に出す。

| ID           | 仕様                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------ |
| bullBoard-e1 | 左カラムの「ジョブキュー」は、新しいタブで開くことが分かるアイコンを付け、新しいタブで開く |
| bullBoard-e2 | `ADMIN_API_TOKEN` を付けると、ログインせずにジョブキューのAPIをGETで読める                 |
| bullBoard-e3 | `ADMIN_API_TOKEN` では、ジョブキューのAPIをGET以外で呼べない                               |

ログインできないスクリプトなどからジョブの件数や失敗理由を調べられるように、読み取り専用のトークンを用意する。`ADMIN_API_TOKEN` を設定しなければ、トークンでは読めない。
