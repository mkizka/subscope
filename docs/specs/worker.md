# Worker仕様

用語は[用語集](../glossary.md)を参照する。

## レコードのインデックス

Tapから受け取ったコミットのレコードをDBに保存・削除する。対象のコレクションは post、repost、like、follow、profile、feed generator、list、listitem。

- index-1: 作成・更新されたレコードを保存する
- index-2: 削除されたレコードを削除する
- index-3: Lexiconのスキーマに合わないレコードはジョブを失敗させずにスキップする
- index-4: null文字を含むレコードは保存しない
- index-5: 削除したレコードは、削除より古いrevのコミットで復活させない
- index-6: 更新したレコードは、更新より古いrevのコミットで古い内容に戻さない
- index-7: revを持たないコミットは、revを比べずに処理する

null文字を含む文字列はPostgreSQLに保存できないため除外する。

コミットは並列に処理され、失敗したジョブはリトライされるため、同じレコードへのコミットが届いた順に処理されるとは限らない。そのためレコードのURIごとに処理済みの最新のrev(リポジトリのコミットを表すTID)を記録する。

## Tapへの登録

追跡アクターをTapに登録し、そのレコードを受け取れるようにする。登録状態が変わりうる操作のあとに`syncTapRepo`ジョブを積み、ジョブを実行した時点のDBの状態から登録するか外すかを決める。ジョブはDBのコミット後に積むので、遅らせずに実行する。

- tap-1: サブスクライバーがフォローしたアカウントをTapに登録する
- tap-2: サブスクライバー以外のフォローではTapに登録しない
- tap-3: サブスクライバーがフォローを外したアカウントは、追跡アクターでなくなればTapから外す
- tap-4: 他のサブスクライバーがフォローしているアカウントはTapから外さない
- tap-5: サブスクライバー以外がフォローを外してもTapから外さない
- tap-6: サブスクライバーは、フォローを外されてもTapから外さない

サブスクライバー本人は、AppViewが me.subsco.sync.subscribeServer の時点でTapに登録する。Tapは登録されたアカウントの過去のレコードをバックフィルしてから、以降のイベントを送る。

## ラベルの保存

モデレーションサービスから受け取ったラベルを保存する。

- label-1: 保存済みのアクターと、そのアクターのレコードに付いたラベルを保存する
- label-2: 保存していないアクターへのラベルは保存しない
- label-3: negがtrueのラベルを受け取ったら、同じラベルを削除する

ラベルは受け取った時点で保存済みのアクターの分だけを保存するため、あとから保存したアクターに以前から付いていたラベルは保存されない。

## ハンドルの解決

ハンドルを持たないアクターのDIDドキュメントを`resolveDid`ジョブで解決し、ハンドルを保存する。

- resolveDid-1: DIDドキュメントのハンドルは、そのハンドルが同じDIDに解決できるときだけ保存する
- resolveDid-2: ハンドルが同じDIDに解決できないときは handle.invalid を保存する
- resolveDid-3: すでにハンドルを持つアクターのハンドルは上書きしない

DIDドキュメントのハンドルは本人以外も自由に書けるため、公式AppViewと同じくハンドルからDIDへの解決と照らしてから保存する。Tapもidentityイベントで同じ検証をしてハンドルを送るので、すでにあるハンドルはそちらを優先する。

## 統計の集計

いいね数やフォロワー数などの統計を、レコードをインデックスしたあとに集計ジョブで数え直す。集計ジョブは10秒遅らせて実行し、続けて来たイベントを1回の集計にまとめる。

- aggregate-1: 同じ対象の集計ジョブが実行待ちの間に来たイベントは、そのジョブにまとめる
- aggregate-2: 集計ジョブの実行中や完了後に来たイベントは、もう一度集計する

## 通知の生成

レコードをインデックスするときに、サブスクライバー宛ての通知を作る。

- notify-1: 通知はサブスクライバー宛てにだけ作る
- notify-2: 自分自身の操作では通知を作らない
- notify-3: いいねされた投稿の作者に like の通知を作る
- notify-4: リポストされた投稿の作者に repost の通知を作る
- notify-5: フォローされたアカウントに follow の通知を作る
- notify-6: リプライの親投稿を含めて4つ上までの投稿の作者に reply の通知を作る
- notify-7: 引用された投稿の作者に quote の、メンションされたアカウントに mention の通知を作る
- notify-8: 1つの投稿から同じ相手への通知は mention > quote > reply の優先順で1件にする

リプライの祖先は保存済みの投稿だけをたどれるので、未保存の投稿より上の作者には通知しない。

v1.0では次の通知は作らない。

- 追跡アクター以外からの通知。Tapから受信しないため届かない。v1.0後に検討する
- 上記以外のreason（starterpack-joined、verified、like-via-repost、subscribed-postなど）
