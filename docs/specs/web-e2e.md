# Web E2E仕様

Webクライアントをブラウザから操作したときの振る舞いを定める。

- 各項目にはIDを振り、E2Eテスト（`apps/web/e2e`）はテスト名の先頭にIDを書いてその項目を検証する
  - 例: `test("login-1: 最初にログインしたアカウントが管理者として登録される")`
- 仕様の追加・変更は、この文書を先に更新してからテストと実装を変更する

## ログイン

atprotoアカウントでOAuthログインする。

- login-1: 最初にログインしたアカウントが管理者として登録される

## タイムライン

ログイン後のトップページの中央カラムにフォロー中のタイムラインを表示する。

- timeline-1: 自分とフォロー中のユーザーの投稿を、新しい投稿ほど下に並べて表示する
- timeline-4: 開くと最新の投稿までスクロールし、上にスクロールすると表示位置を保ったまま古い投稿を読み込む

## 投稿欄

タイムラインの中央カラムの下に、1行に畳んだ投稿欄を表示する。

- post-form-1: 畳んだ投稿欄をクリックすると広がり、投稿した内容がタイムラインの一番下に表示される
- post-form-2: 300字を超えると投稿ボタンを押せない
- post-form-3: 画像を添付してALTを入力して投稿すると、タイムラインの投稿にALT付きの画像が表示される
- post-form-4: 画像は4枚まで添付でき、4枚添付すると画像を追加できない

## スレッド

- thread-1: タイムラインの投稿を選ぶと、右カラムにその投稿のスレッド（親投稿と返信）が出る
- thread-2: URLの `?thread=投稿のAT URI` で、右カラムにその投稿のスレッドが開く
- thread-3: スレッドを閉じると、右カラムが通知に戻る

## 通知

PCでは右カラム、モバイルではヘッダーの🔔から全画面で開く。通知になるのは追跡中のユーザーからのものだけ。

- notification-1: 自分の投稿がいいね・リポストされると、相手の名前と対象の投稿の本文が通知に出る
- notification-2: フォローされると、相手の名前が通知に出る
- notification-3: 自分の投稿にリプライ・引用・メンションされると、その投稿が通知に出る
- notification-4: 通知は新しい順に並び、下までスクロールすると古い通知を読み込む
- notification-5: 未読の通知は背景色で区別され、通知を開いた後に再表示すると既読になる
- notification-6: モバイルでは、未読があるときヘッダーの🔔に未読数が出る

## プロフィール

- profile-1: 左カラムの「プロフィール」を選ぶと、中央カラムに自分のプロフィール（名前、ハンドル、フォロー数、フォロワー数、投稿一覧）が出る
- profile-2: URLの `?profile=ハンドル` で、右カラムにそのユーザーのプロフィールの簡易表示が開く
- profile-3: 簡易表示を閉じると、右カラムが通知に戻る
- profile-4: 簡易表示から、中央カラムのプロフィール全体ページに移動できる

## 投稿のツールバー

タイムラインの投稿にホバーするとツールバーを出す。

- post-toolbar-1: いいねボタンで投稿にいいねし、もう一度押すと取り消す
- post-toolbar-2: リポストボタンで投稿をリポストし、もう一度押すと取り消す
